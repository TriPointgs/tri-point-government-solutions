# Domain documentation

Use one glossary for the repository. Read `GLOSSARY.md` at the repository root when it exists. Read relevant decision records in `docs/adr/` before proposing a change. Use the glossary's terms in tickets, specs, code discussions, and documentation.

Continue normally when these files have not been created. Add glossary entries and decision records when the team establishes a term or makes a decision. If a proposal conflicts with a recorded decision, identify that record and explain what needs to change.
